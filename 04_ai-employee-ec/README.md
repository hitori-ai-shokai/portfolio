# EC運営の「AI社員」デモ(ポートフォリオ #4)

ECショップの毎日の定型業務を、AI(Claude)が定時に自動でこなす仕組みの見本です。**データはすべて架空**です(店名・お客様・住所・メールはダミー)。

## AI社員がやること(1日の流れ)
| 時刻 | 仕事 | 中身 | 人に回すもの |
|---|---|---|---|
| 8:30 | 注文チェック | 前日の注文に点数をつけ、不正の疑いがあるものを見つける | 点数が3点以上の注文 |
| 8:30 | 日次レポート | 売上・商品別の売上・在庫が何日もつか | 発注の判断 |
| 9:00 / 13:00 / 18:00 | 問い合わせの返信案 | 種類を分け、返品は規定どおりか判定してから返信案を書く | 規定外の返品、値引き、配送先の変更など |

**AIは決めない。下書きと判定の理由までを作り、最後の判断と送信は人が行う**、という線引きで設計しています。

## 中身
- `ec_tools.py`:注文チェック・返品の規定判定・日次レポート(ルールで決められる部分は、AIではなくプログラムで確実に処理)
- `config.json`:判定の基準(点数・返品規定・在庫の警告日数)。基準を変えるときはここだけ直す
- `指示書/`:AI社員への指示書(定期実行するときの指示)
- `sample_data/`:架空の注文17件・在庫5商品・問い合わせ6件
- `output/`:2026-10-18 分の実行結果(下記)
- `tests/`:自動テスト11件

## 実行結果の例(2026-10-18)
- **注文チェック**:15件のうち4件を「要確認(人へ)」に回した
  - A1004(6点):初めての注文で高額 / 請求先と配送先が違う / 配送先に「転送」 / 使い捨てメール
  - A1009・A1010(5点):同じ配送先に別名義の高額注文が2件
  - A1015(3点):同じ商品を6個 / 配送先に「私書箱」
- **返品判定**:3件のうち1件が規定内(未開封・4日)。2件は人の確認へ(開封済みで不良の可能性 / 未配達の記録)
- **返信案**:6件のうち2件はそのまま送れる案、4件は人の確認待ち(`output/返信案_2026-10-18.md`)
- **日次レポート**:売上252,800円。在庫が1日分前後の商品(キャンドル・ランプ)に発注の警告

## 動かし方
```
python ec_tools.py --date 2026-10-18
python -m unittest discover -s tests
```
Python 3.10 以降、標準ライブラリのみ。

## 実際の店舗に入れるとき
- 注文・問い合わせ・在庫は、ショップの管理画面からのCSV出力、またはAPI連携で取り込みます(Shopify・BASE・楽天など)。
- サーバーやGitHubはお客様名義のものを使い、当方は招待を受けて作業します。
- 判定の基準(何点で人に回すか)は、最初の2週間の結果を見てお客様と調整します。
